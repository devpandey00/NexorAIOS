# NexorAIOS External Tooling Matrix

Checked against the current NexorAIOS architecture and the canonical master workflow specification.

## Installed now

| Tool | Repository | Nexor role | Integration mode |
|---|---|---|---|
| n8n | https://github.com/n8n-io/n8n | External workflow/approval orchestration adapter | Optional isolated Docker service in `docker/docker-compose.integrations.yml` |

n8n is intentionally isolated from the Nexor monorepo. Nexor remains the source of truth for users, leads, CRM state, approvals, audit records and business workflows.

| Tool | Repository | Use in Nexor | Why not copy the whole repo |
|---|---|---|---|
| Playwright | https://github.com/microsoft/playwright | Browser automation, E2E, agent browser control | Library/runtime dependency; not a standalone product to merge |
| Crawlee | https://github.com/apify/crawlee | Reliable crawling and lead/website discovery | Add as a targeted crawler dependency/worker |

| Remotion | https://github.com/remotion-dev/remotion | Programmatic video rendering | Use renderer/bundler packages in a dedicated video worker |
| listmonk | https://github.com/knadh/listmonk | Newsletter/bulk email campaign reference | Separate Go service; integrate over API when needed |

## Important architectural decision

The Nexor master specification explicitly says to keep Nexor as the central UI, database, AI-agent layer and workflow system, and to use external projects as architecture/integration references or separately deployed services rather than blindly merging complete repositories.

Therefore this matrix deliberately separates:

- **installed runtime services** — things we can safely run beside Nexor;
- **library dependencies** — things that belong in a specific package/worker and must be added with the lockfile regenerated by a real pnpm environment;
- **external services** — large applications that should remain separately deployed and connected through API/webhooks.

No third-party service is considered LIVE until Nexor receives a real provider response and persists the result. Missing credentials must produce `CONFIGURATION_REQUIRED`, not fake success.
